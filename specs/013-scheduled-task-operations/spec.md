## User Scenarios & Testing

### User Story 1 - 查看、补跑和暂停任务 (Priority: P1)

运维人员希望查看已登记任务的运行状态，按需补跑或暂停自动触发，以便在无人值守时仍能核对运行结果。

**Independent Test**: 用一个可控 Agent 启动服务，验证登记、手动执行、查看历史、暂停与恢复。

1. **Given** Agent 配置了定时规则，**When** 服务启动，**Then** 列表显示任务、归属、规则、下次触发时间、上次结果、累计次数及启用状态。新任务默认启用且次数为 0。
2. **Given** 运维人员暂停了一个任务，**When** 到达触发时间，**Then** 任务不运行也不新增执行记录。运维人员仍可手动执行一次。
3. **Given** 任务执行完成，**When** 运维人员刷新列表并查看历史，**Then** 累计次数增加一次，可查到本次结果、关联会话及耗时，失败时显示可读且不含敏感信息的原因。

### User Story 2 - 服务重启后继续运行 (Priority: P1)

运维人员重启服务后，仍可核对历史并继续使用已有记忆与任务状态。

**Independent Test**: 完成对话、写入核心记忆并触发定时后，使用原工作区和数据启动新实例。

1. **Given** 任务已执行并停用，**When** 重启，**Then** 任务身份、停用状态、累计次数、上次结果及历史仍可核对。启用的任务重新注册并显示未来触发时间。
2. **Given** 已有对话、核心记忆和调用审计，**When** 重启后再次对话，**Then** 能查到原会话和核心记忆，且审计保留旧记录并继续追加。
3. **Given** 定义被移除或任务键变化，**When** 服务重新协调定义，**Then** 原任务停止调度并从活动列表移除，旧历史仍按稳定身份可查。

### User Story 3 - 多 Agent 稳定运行 (Priority: P1)

维护者希望两个 Agent 共用同一实例，同时隔离工具、会话与定时失败。

**Independent Test**: 为 A 和 B 配置不同工具及同名任务键，让 A 执行失败并验证 B 下个触发正常。

1. **Given** A 和 B 配置了不同工具，**When** 交替对话与定时触发，**Then** 彼此的工具列表及会话历史不串用，A 的定时失败不会阻断 B。
2. **Given** 天气任务到点运行，**When** Agent 获取天气并推送，**Then** 接收端实际收到通知，工具与模型审计逐次对应，同一 Agent 重复运行时复用定时会话。
3. **Given** 通知目标未获白名单许可，**When** Agent 尝试推送，**Then** 推送被拦截，工具审计记录失败，后续触发仍可执行。
4. **Given** 模型、工具或通知阻塞，或外部 MCP 连接失败，**When** 系统执行或启动，**Then** 阻塞调用按超时结束，MCP 失败记录告警并跳过该服务工具。

### Edge Cases

- 同一 Agent 的定时会话仍受原有进程内互斥保护。自动或手动重叠触发均跳过，且不计入执行次数。其他 Agent 可独立执行。
- 多个活动任务的配置键相同，旧版兼容入口拒绝歧义请求。新版入口可按任务身份或按 Agent 与配置键精确定位。
- 无效输入、未知任务、退役任务的运行请求与停启请求均返回现有统一错误格式。已退役任务历史仍可按任务身份查询。

## Requirements

### Functional Requirements

- **FR-001**: 从 Agent 的唯一配置来源动态注册规则，支持明确时区。状态和历史与定义分离，保持每个 Agent 内的任务键唯一。
- **FR-002**: 为每个任务保留跨重启稳定、跨 Agent 唯一的身份。登记时保留已知运行状态，移除定义时保留旧历史。
- **FR-003**: 到点仅执行已启用的活动任务。手动补跑一次不受启用状态限制。自动与手动触发共享互斥及同一 Agent 执行链路。
- **FR-004**: 每次实际执行无论成败均记录一条历史，并一致更新累计次数、上次结果、上次与下次时间。跳过时不增加次数或历史。
- **FR-005**: 提供任务列表、执行历史、立即执行、启用和停用能力。旧版按键定位在多 Agent 同键时报告冲突。
- **FR-006**: 管理台提供定时任务列表以及每行立即执行、启停操作。页面显示空、加载、操作中和失败状态，写操作完成后显示最新状态。
- **FR-007**: 使用同一份工作区及数据重启时，保留会话历史、核心记忆、定时任务运行状态与历史、模型调用审计。
- **FR-008**: 两个 Agent 在同一实例并存时，隔离可用工具、会话与调度失败。定时调用固定使用现有定时会话身份并复用会话。
- **FR-009**: 保持模型、工具与通知的超时保护，定时运行也受单次 Agent 执行 60 秒上限约束。按会话 ID 串联日志，记录可读且脱敏的错误，MCP 连接失败可降级启动。
- **FR-010**: 以可控模型和本地测试替身覆盖无密钥机制验收。真实模型、天气及 webhook 验收独立，涵盖准确审计、会话复用与白名单拒绝。交付 Demo 前置配置示例、核对步骤及管理接口说明。

### Key Entities

- **定时定义**：Agent 持有的任务键、执行规则、时区与触发消息。
- **运行状态**：稳定任务身份、归属、启用及退役标记、时间和执行计数。
- **执行历史**：任务身份、可用时关联会话、开始时间、耗时及结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 一个新登记任务显示 0 次，补跑后显示 1 次并可查 1 条历史。停用后至少一个自动触发点不产生记录。
- **SC-002**: 重启后会话、核心记忆、定时状态及历史、模型审计四类证据均可核对。
- **SC-003**: 同实例两个 Agent 的工具、会话、调度三条隔离检查全部通过。
- **SC-004**: 天气场景每次成功执行各发起一次天气查询与通知，接收端收到一次推送，两次触发复用一个定时会话。拒绝场景留下失败审计且推送数为零。
- **SC-005**: 单次 Agent 调用超时上限为 60 秒，超时可观察，故障后后续触发可执行，单个外部 MCP 连接失败仍可启动。

## Assumptions

- 本节沿用核心阶段的单进程部署、现有权限模型、记忆后端及统一执行链路。
- 真实外部验收依赖操作者提供的本地凭证和测试通知渠道。无密钥验证与真实验证分别报告。
- 本节范围限于调度运行控制和课件的可靠性验收。Agent 生命周期 API、在线编辑调度定义、业务 Agent 发布、分布式协调与补偿重跑留在后续阶段。
