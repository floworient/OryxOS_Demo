## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成带工具的多轮推理 (Priority: P1)

集成方提交用户消息，Agent 按需调用工具并利用结果回答；持续请求工具时能够停止。

**Why this priority**: 形成 Agent 的核心执行能力。
**Independent Test**: 模型桩先请求工具再回复，核对次数、结果关联和消息顺序。
**Acceptance Scenarios**:

1. **Given** 模型直接回复，**When** 处理消息，**Then** 仅调用一次模型并返回文本。
2. **Given** 模型请求多个工具，**When** 处理响应，**Then** 顺序逐个执行，按调用标识回填，下次推理能看到完整链路。
3. **Given** 模型持续请求工具，**When** 达到上限，**Then** 不再调用模型，返回“达到最大轮数，已停止”，保留已发生的消息。
4. **Given** 模型超时或抛错，**When** 处理失败，**Then** 向调用方报告，停止后续执行，不自动切换供应商。

### User Story 2 - 使用最新且受控的上下文 (Priority: P1)

Agent 设计者修改正文、Bootstrap 或 Skill 绑定后，下一次构建即生效；历史受控且保留完整工具关联。

**Why this priority**: 上下文决定推理正确性及隔离。
**Independent Test**: 临时目录中编辑文件和绑定，重建上下文；构造超过 20 轮历史核对裁剪。
**Acceptance Scenarios**:

1. **Given** 指令、Bootstrap 和可选记忆，**When** 构建上下文，**Then** 按系统指令、可选记忆、近期历史、工具定义顺序组装，系统指令末尾含日期时间。
2. **Given** 历史超过限制，**When** 构建上下文，**Then** 选择最近完整用户轮次，保留当前轮及成组工具调用与结果，不删除完整历史。
3. **Given** 绑定公共 Skill，**When** 构建上下文，**Then** 只呈现名称、描述和本地路径，不呈现正文、脚本或未绑定 Skill。
4. **Given** 引用缺失或路径越界，**When** 加载上下文，**Then** 缺失 Skill 或越界报错，缺失 Bootstrap 发出定位警告。
5. **Given** 修改正文、元数据或绑定，**When** 下一次构建，**Then** 无需重启可见新内容。

### User Story 3 - 追溯每次受控工具执行 (Priority: P1)

运维人员能追溯成功、失败及拒绝原因，未授权调用不产生副作用。

**Why this priority**: 工具必须统一受控且可审计。
**Independent Test**: 工具桩和策略桩制造成功、失败、异常、拒绝及重试，检查执行计数与持久记录。
**Acceptance Scenarios**:

1. **Given** 工具合法可见且检查通过，**When** 执行，**Then** 仅统一执行器调用工具，成功及结果落审计。
2. **Given** 工具失败或抛异常，**When** 执行结束，**Then** 原因落审计并反馈模型，不伪装成功。
3. **Given** 未注册、不可见或安全拒绝，**When** 请求执行，**Then** 工具执行零次，拒绝被审计。
4. **Given** 明确可重试的失败，**When** 重试，**Then** 指数退避最多重试三次，每次尝试均审计；安全拒绝、参数错误和未标记失败不重试。

### User Story 4 - 统一处理与跨重启恢复 (Priority: P1)

集成方通过统一入口处理消息，处理期间能获取当前 Agent，退出后不污染后续请求；已保存对话可恢复。

**Why this priority**: 保障后续接入复用同一链路。
**Independent Test**: 处理期间检查当前 Agent；正常及异常后复用线程；重建存储恢复会话。
**Acceptance Scenarios**:

1. **Given** 合法会话，**When** 处理消息，**Then** 当前 Agent 正确，成功后保存完整历史。
2. **Given** 处理抛异常，**When** 离开入口，**Then** 当前 Agent 上下文被清除，原异常可见。
3. **Given** 已保存会话和审计，**When** 重建存储，**Then** 恢复消息及工具关联；不同渠道、用户、Agent 互不混淆。
4. **Given** 审计或会话保存失败，**When** 处理结束，**Then** 明确失败，不报告已可靠保存。

### Edge Cases

- 空工具列表、空最终文本、一轮多个调用均保持顺序与标识；达到上限的终止说明进入会话。
- 裁剪只影响模型输入；不能拆散工具消息，也不能删除已保存历史。
- 路径穿越、绝对绑定、断链、越界目标、绑定后的文件逃逸均拒绝。采用项目内普通 `.link` 相对引用，不依赖操作系统链接权限；公共 Skill 不复制，真实路径边界不放宽。
- 异常不得遗留当前 Agent；损坏的历史明确报错；凭据不得进入错误文本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 自行编排循环，默认最多 10 次模型调用，无工具请求即返回。
- **FR-002**: 系统 MUST 累积用户输入、模型回复、调用标识、工具结果及最终回答。
- **FR-003**: 系统 MUST 顺序执行多个工具，每个正常请求一次；模型失败终止且错误可见。
- **FR-004**: 系统 MUST 统一构建上下文，系统指令末尾含日期时间，可选长期记忆未启用则跳过，工具仅含当前 Agent 可见集合。
- **FR-005**: 上下文 MUST 默认保留最近 20 个用户轮次，工具调用与结果不可拆散，完整会话不因裁剪丢失。
- **FR-006**: 系统 MUST 每次读取正文和 Bootstrap，不缓存；Bootstrap 缺失警告，非法或越界引用报错。
- **FR-007**: Skill MUST 由Agent skills/ 下普通 .link 相对引用文件集合唯一绑定，每次只加载绑定元数据并验证真实路径，不预载正文或未绑定资源。
- **FR-008**: 工具 MUST 统一经过注册解析、可见性判断、安全检查和执行，默认拒绝未经策略放行的调用。
- **FR-009**: 每次工具尝试 MUST 持久记录会话、名称、参数、结果、成功、错误、耗时和时间；审计失败阻断处理。
- **FR-010**: 系统 MUST 只对明确可重试的失败指数退避，最多重试三次，不重试安全拒绝和参数错误。
- **FR-011**: 统一入口 MUST 设置当前 Agent，成功或异常时清除；成功或迭代上限结束后保存完整会话。
- **FR-012**: 会话 MUST 按渠道、用户、Agent 联合标识；已保存历史和工具审计跨存储重建恢复，写入失败不得报告成功。
- **FR-013**: 系统 MUST 保持模型自动执行工具关闭，沿用现有路由及模型审计，不泄露凭据。

### Key Entities

- **会话**：身份、完整顺序消息、状态与时间。
- **工具调用**：标识、名称、参数及关联结果。
- **工具审计**：每次尝试的持久记录。
- **上下文**：当前指令、绑定元数据、可选记忆、近期历史及可见工具。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 持续请求工具时恰好在第 10 次模型调用后终止，越界调用零次。
- **SC-002**: 非重试合法请求各执行一次，拒绝场景执行零次，消息关联保留率 100%。
- **SC-003**: 超过 20 轮时近期轮次及工具关联保留正确，完整历史丢失数为零。
- **SC-004**: 正常及异常后当前 Agent 残留为零；存储重建后会话与成功、失败审计恢复率 100%。
- **SC-005**: 下一次构建反映文件与绑定修改，未绑定或完整 Skill 正文泄入数量为零。

## Assumptions

- 第 16 节 Provider 已存在；自动验收使用模型及工具桩、临时目录和 SQLite。
- 本节提供最小会话保存与读取；归档命令、并发会话写入治理和管理接口留后续。
- 不实现 CLI、初始化、真实 HTTP 工具、Memory 后端、MCP、通知、调度、流式输出、并行工具、Agent 委托或上下文压缩。
- 真实天气 Demo 依赖后续 HTTP 工具与接入能力，单独报告待集成，不以桩测试冒充通过。
- 保留既有目录名称避免引用失效；名称中的 cli 不表示本节包含 CLI。
