## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初始化工作区并加载 Agent (Priority: P1)

开发者在一个空目录执行初始化命令，得到一套可编辑的工作区结构和 Bootstrap 文件。开发者手写或放入一个 Agent 目录后启动对话命令，系统读取该 Agent 的定义并让它进入可对话状态。

**Why this priority**: 没有工作区和可加载的 Agent，后续所有对话与工具能力都无从谈起。这是 US-2 的入口。

**Independent Test**: 在空目录执行初始化，检查目录与文件齐全；放入一个最小 Agent 定义，启动对话命令，确认该 Agent 可被选中并开始对话。

**Acceptance Scenarios**:

1. **Given** 一个空目录，**When** 开发者执行初始化命令，**Then** 系统创建 Agent、公共 Skill、产出物、记忆、会话和日志等目录，以及项目背景、人格、用户偏好三个 Bootstrap 文件。
2. **Given** 工作区已经初始化并存在用户修改过的文件，**When** 再次执行初始化命令，**Then** 已有目录和文件不被覆盖，命令以成功状态结束并说明未做改动。
3. **Given** 工作区中存在多个合法 Agent 目录，**When** 开发者用 `--profile` 指定其中一个启动对话，**Then** 系统只加载该 Agent 的定义并进入对话状态。
4. **Given** 一个 Agent 定义引用了不存在的供应商或未注册的工具，**When** 系统加载全部 Agent，**Then** 该 Agent 被标记为不可用并给出具体原因，其他合法 Agent 仍可正常使用。
5. **Given** 工作区中只有一个合法 Agent，**When** 开发者不指定 `--profile` 启动对话，**Then** 系统自动选用该 Agent。

---

### User Story 2 - 多轮对话与工具循环 (Priority: P1)

开发者在终端与 Agent 多轮对话。Agent 在回答过程中自行决定是否调用工具，系统执行工具并把结果交回模型，直到模型给出最终回答。对话历史在同一次会话内持续累积。

**Why this priority**: 这是 Agent 区别于普通聊天机器人的核心行为，也是 Demo 一能够成立的前提。

**Independent Test**: 用受控模型桩让第一轮返回一个工具调用、第二轮返回最终文本，检查工具被执行一次、结果被回填、最终回答出现在终端；再追加一轮消息，确认历史被保留。

**Acceptance Scenarios**:

1. **Given** 一个已加载的 Agent，**When** 用户输入一条消息且模型直接返回文本，**Then** 终端显示该文本，本轮结束。
2. **Given** 模型返回一个工具调用意图，**When** 系统处理该响应，**Then** 系统执行一次对应工具，把结果交回模型继续推理，直到模型不再请求工具。
3. **Given** 模型连续请求多个工具，**When** 系统执行这些调用，**Then** 每个请求按顺序各执行一次，不并行、不重复执行。
4. **Given** 同一次对话中用户先后输入多条消息，**When** 每条消息处理完成，**Then** 后续轮次能够看到之前的用户消息、模型回复和工具结果。
5. **Given** 模型达到最大迭代次数仍在请求工具，**When** 达到上限，**Then** 系统停止循环并向用户显示明确的终止说明，不无限等待。
6. **Given** 一次工具执行失败，**When** 失败结果可重试且未超过重试上限，**Then** 系统按退避策略重试；不可重试或超过上限时，把失败信息作为工具结果交回模型。

---

### User Story 3 - 受控访问外部 HTTP 资源 (Priority: P2)

Agent 需要查询外部数据时调用内置 HTTP 工具。只有域名白名单内的地址才会真正发出请求；白名单外或非法的地址被拦截，模型收到明确的失败结果并可以据此调整回答。

**Why this priority**: 外部访问是 Agent 产生实际价值的主要方式，同时也是安全边界的第一道闸门。

**Independent Test**: 分别请求白名单内地址、白名单外地址和格式非法地址，检查前两者中仅白名单内地址产生真实网络请求，三者都以可理解的结果回传给模型。

**Acceptance Scenarios**:

1. **Given** 目标地址的域名在白名单内，**When** 模型请求该地址，**Then** 系统发出一次 HTTP 请求并把响应内容作为工具结果交回模型。
2. **Given** 目标地址的域名不在白名单内，**When** 模型请求该地址，**Then** 系统不发出任何网络请求，并把拒绝原因交回模型。
3. **Given** 目标地址格式非法或协议不受支持，**When** 模型请求该地址，**Then** 系统在发起请求前拒绝，并说明原因。
4. **Given** 外部服务返回错误或超时，**When** 工具执行结束，**Then** 失败信息作为工具结果交回模型，对话不中断。

---

### User Story 4 - 上下文组装与历史管理 (Priority: P2)

每轮模型调用前，系统把 Agent 指令、项目背景、人格、用户偏好、当前时间和可用工具列表组装成完整上下文，并按配置保留最近若干轮对话。开发者修改 Agent 指令后，下一轮对话即生效，无需重启。

**Why this priority**: 上下文决定模型能否正确理解任务；历史截断决定长对话是否稳定；即时生效决定调试效率。

**Independent Test**: 在 Agent 定义中写入可识别的指令文本并对话，检查模型输入包含该文本、Bootstrap 内容与当前日期；修改指令后不重启再次对话，检查新内容进入下一轮输入；构造超长历史，检查只保留最近若干轮。

**Acceptance Scenarios**:

1. **Given** 一个已加载的 Agent，**When** 组装一轮模型输入，**Then** 输入包含该 Agent 的任务指令正文、已配置的 Bootstrap 内容和当前日期时间。
2. **Given** Agent 定义只允许使用部分工具，**When** 组装模型输入，**Then** 只包含该 Agent 声明的工具，不包含其他工具。
3. **Given** 开发者修改了 Agent 指令正文，**When** 下一轮对话开始，**Then** 新内容立即出现在模型输入中，无需重启进程。
4. **Given** 对话历史超过配置的最大轮数，**When** 组装下一轮输入，**Then** 保留系统指令和最近若干轮对话，丢弃更早的对话。

---

### User Story 5 - 会话控制与退出 (Priority: P3)

开发者在交互过程中可以随时退出；也可以用单条消息模式发起一次请求后自动结束。会话身份在同一进程内保持稳定，不同 Agent 的对话互不混淆。

**Why this priority**: 这些是日常使用和自动化验证的基础体验，不实现会让调试和验收变得笨拙。

**Independent Test**: 启动对话后输入退出指令，检查进程正常结束；用单条消息模式执行一次请求，检查输出后立即退出；切换 Agent 启动，确认历史不串。

**Acceptance Scenarios**:

1. **Given** 交互对话正在进行，**When** 用户输入退出指令，**Then** 进程正常结束并释放会话。
2. **Given** 用户使用单条消息模式，**When** 模型返回最终回答，**Then** 终端显示回答并自动结束进程。
3. **Given** 同一用户在两个不同 Agent 上分别对话，**When** 切换 Agent，**Then** 两个会话的历史互不可见。
4. **Given** 用户输入为空或只有空白字符，**When** 提交，**Then** 系统不调用模型，提示后继续等待输入。

---

### Edge Cases

- Agent 定义缺少必填字段或格式错误时，该 Agent 不可用并指出具体字段，其他 Agent 不受影响。
- Agent 声明的 Bootstrap 文件不存在时，该 Agent 不可用并给出缺失文件路径。
- 指定的 `--profile` 不存在时，命令以非零状态退出，并列出当前可用的 Agent 名称。
- 工作区尚未初始化就启动对话时，提示先执行初始化，不以晦涩错误崩溃。
- `oryxos init` 在只读目录或权限不足时，给出可操作的错误并以非零状态退出，不留下半成品结构。
- 模型返回空文本或只有空白字符时，作为异常结果提示用户，不静默结束。
- 工具返回内容过长时，应截断到配置上限并标记截断，避免撑爆上下文。
- 模型在同一轮响应中重复请求同一个工具和同一组参数时，这是模型的显式意图，仍按每次请求各执行一次处理；系统不得额外自动执行。
- 外部请求超时时间必须可配置且有默认值；超时不得导致整个进程挂起。
- 白名单未配置或为空时，所有外部请求一律被拒绝；Agent 仍可正常对话，并收到明确的可配置提示。
- 最大迭代次数或最大历史轮数配置为非法值时，加载阶段拒绝该 Agent 并说明取值要求。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供工作区初始化命令，创建 Agent、公共 Skill、产出物、记忆、会话和日志目录，以及项目背景、人格、用户偏好三个 Bootstrap 文件。
- **FR-002**: 初始化命令 MUST 幂等：已存在的目录和文件一律不覆盖；重复执行 MUST 以成功状态结束并说明未做改动。
- **FR-003**: 系统 MUST 在启动对话时扫描工作区中的 Agent 目录，从 Agent 定义的配置部分派生运行配置，从正文部分获得任务指令。
- **FR-004**: 系统 MUST 校验每个 Agent 引用的供应商是否存在、声明的工具是否已注册、Bootstrap 文件是否存在；校验失败的 Agent MUST 被标记为不可用并记录具体原因，其他 Agent MUST 继续可用。
- **FR-005**: 对话命令 MUST 支持按名称选择 Agent（CLI 中以 `--profile` 参数指定 Agent 名称）；未指定时，若工作区只有一个合法 Agent 则自动选用，否则 MUST 要求显式指定并列出可选 Agent。
- **FR-006**: 对话命令 MUST 支持交互式多轮对话、退出指令，以及发送单条消息后自动结束的模式。
- **FR-007**: 每条用户消息 MUST 触发一次完整的推理循环：调用模型；若模型请求工具，则执行工具并把结果交回模型；重复直到模型不再请求工具或达到迭代上限。
- **FR-008**: 推理循环 MUST 有最大迭代次数，默认 10，可由 Agent 配置覆盖；达到上限时 MUST 停止并告知用户。
- **FR-009**: 模型请求的每个工具调用 MUST 恰好执行一次，并在同一轮内按请求顺序执行；系统 MUST NOT 并行执行工具，也 MUST NOT 由底层能力自动执行工具。
- **FR-010**: 工具执行失败时，失败信息 MUST 作为工具结果交回模型；可重试的失败 MUST 按退避策略重试，默认最多三次；不可重试的失败 MUST NOT 重试。
- **FR-011**: 系统 MUST 提供 HTTP GET 工具；只有域名白名单内的地址才能发出真实请求，白名单外、协议不支持或格式非法的地址 MUST 在发起请求前被拒绝并说明原因。白名单 MUST 由运营方在全局配置中统一声明并对所有 Agent 生效；Agent 定义 MUST NOT 自行扩充允许访问的域名。白名单未配置或为空时，MUST 拒绝全部外部请求。
- **FR-012**: HTTP 工具 MUST 有可配置的超时和响应长度上限；超时 MUST NOT 导致对话进程挂起。
- **FR-013**: 每轮模型输入 MUST 包含 Agent 任务指令正文、配置的 Bootstrap 内容、当前日期时间、可用工具列表和对话历史。
- **FR-014**: 每轮模型输入中的工具列表 MUST 只包含当前 Agent 声明的工具。
- **FR-015**: 系统 MUST 在每轮组装上下文时重新读取 Agent 定义与 Bootstrap，使修改在下一轮生效，不需要重启进程。
- **FR-016**: 对话历史 MUST 按最大轮数截断，默认 20 轮；截断 MUST 保留系统指令和最近若干轮，并 MUST NOT 把工具结果与其对应的调用拆散。
- **FR-017**: 会话 MUST 按接入渠道、用户和 Agent 联合标识；同一进程内同一标识的对话历史 MUST 持续累积，不同 Agent 的会话 MUST 相互隔离。
- **FR-018**: 每次模型调用和工具调用 MUST 产生可追溯记录，包含标识、输入输出、成功与否、耗时和发生时间；工具调用记录 MUST 包含工具名、参数、结果与错误信息。两类记录 MUST 在本阶段即持久保存为 `llm_calls` 与 `tool_invocations` 两份数据，进程退出后不丢失，不得只保留在内存中。
- **FR-019**: 系统 MUST NOT 在终端输出、日志或错误信息中暴露供应商凭据或其他秘密值。
- **FR-020**: 命令遇到不可恢复的配置错误时 MUST 以非零状态退出，并给出包含 Agent 名称、字段或文件路径的可操作错误信息。
- **FR-021**: 供应商定义与凭据 MUST 由部署侧的应用级配置提供，不随工作区分发；工作区中的 Agent 定义 MUST NOT 能新增或改写供应商，只能按名称引用已配置的供应商。

### Key Entities

- **工作区（Workspace）**: 用户维护的一套目录与文件，包含 Agent 定义、公共 Skill、Bootstrap、记忆、会话、产出物和日志。
- **Agent 定义（Agent Profile）**: 一个目录及其定义文件；配置部分描述供应商、模型参数、工具、Bootstrap 和运行限制，正文部分是任务指令。
- **会话（Session）**: 一次持续对话的上下文容器，按渠道、用户和 Agent 联合标识，保存完整消息序列。
- **消息（Message）**: 用户输入、模型回复或工具结果，按发生顺序组成对话历史。
- **工具（Tool）**: 可被模型请求执行的能力定义，包含名称、说明、输入结构和执行结果；本阶段至少包含一个受控 HTTP GET 工具。
- **工具执行记录（Tool Invocation）**: 一次工具调用的审计信息，包含工具名、参数、结果、成功标识、错误信息、耗时和时间。
- **模型调用记录（Model Call）**: 一次模型调用的成本与可观测信息，包含供应商、模型、token 用量、耗时和时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户能在 5 分钟内完成「初始化工作区 + 放入一个 Agent + 发起第一次对话」。
- **SC-002**: 在需要一次工具调用的验证场景中，100% 的工具调用只被执行一次，0 次重复执行、0 次自动执行。
- **SC-003**: 在白名单拦截验证中，100% 的白名单外地址在发出网络请求前被拒绝，外发请求次数为 0；白名单为空时同样为 0。
- **SC-004**: 在 Agent 配置错误的验证场景中，100% 的错误被定位到具体 Agent 与字段，合法 Agent 的可用率保持 100%。
- **SC-005**: 模型返回最终回答后，终端在 1 秒内呈现结果（不含模型自身响应时间）。
- **SC-006**: 对话历史超过配置上限时，后续输入仍包含最近 20 轮（或配置值）对话，且不超出上下文预算。
- **SC-007**: 达到最大迭代次数时，用户在 1 秒内看到明确终止说明，进程保持可继续对话状态。
- **SC-008**: 100% 的模型调用与工具调用产生包含所需字段的可追溯记录，且记录在进程重启后仍可被查询到。

## Assumptions

- 本阶段只实现一个内置 HTTP GET 工具；文件、Shell、通知、MCP 与记忆工具在后续能力中交付。
- 本阶段会话保存在进程内存中，进程退出后不恢复；跨重启恢复随持久化能力交付。该取舍不改变会话标识与消息结构。会话内存态与审计表持久化并存：`llm_calls` 和 `tool_invocations` 在本阶段就写入数据库，不能等审计查询界面交付后再补。
- Agent 目录由开发者手工创建和编辑；`profile create/list/show/delete` 等管理命令不在本阶段范围。
- 供应商定义、白名单、超时与长度上限等运行参数由部署侧统一配置；工作区只承载 Agent、Skill 与 Bootstrap 等业务侧内容。
- 本阶段为单用户本地 CLI 场景，不处理多用户并发、鉴权或远程接入。
- 核心阶段不实现流式输出、并行工具调用、Agent 间委托和上下文自动摘要。
- 工具重试仅针对明确标记为可重试的失败；被安全策略拒绝、参数非法等失败不重试。
- 供应商调用失败时直接向用户报错，不切换到其他供应商。
- 工作区初始化不自动创建 Agent；初始化后的第一个 Agent 由用户手工创建，或由后续管理能力生成。
