## Context

运维人员需要显式允许 Agent 访问额外业务目录，确保文件、命令、网络和通知的越界请求在执行前拒绝；失败应可解释、可审计且不暴露秘密。现有基础授权、工具可见性、Skill 绑定和调用审计是前序依赖，本功能补齐管理配置和拒绝链路的可验证性。

### IO 与脱敏职责的边界

- **校验 IO**：为授权进行必要的路径元数据检查、真实路径解析、`.link` 和 Skill 元数据读取；“零业务 IO”不禁止这些必要检查。
- **业务 IO**：读取目标文件正文、写入/修改文件、启动进程、HTTP 请求及通知发送。被拒绝操作必须在这些动作前停止；`edit_file` 必须先通过 READ 和 WRITE 授权，再读取目标正文。校验元数据不等于业务正文读取。
- **安全错误消息**：固定类别，不包含目标或凭证，约束模型结果及错误日志。
- **审计输入**：独立检查请求参数在持久化前的脱敏；安全错误消息不能代替输入脱敏，Shell `arguments` 中的凭证也不得明文入库。复用已有审计写入链路不意味着冻结其参数脱敏函数。

## User Scenarios & Testing

### User Story 1 - 显式授权额外业务目录 (Priority: P1)

管理员配置业务数据目录后，Agent 可读写其中的文件；未授权目录仍不可访问，Skill 绑定和只读权限不因宽泛目录授权而扩大。

**Why this priority**: 补齐 005 尚未实现的额外文件根，是本次新增的主要业务能力。

**Independent Test**: 使用临时 Agent、公共 Skill 和普通业务目录，验证额外根读写、默认拒绝及 Skill 保护。

**Acceptance Scenarios**:

1. **Given** 未配置额外目录，**When** 读取 Agent 自有文件和已绑定 Skill、写入 Agent 文件，**Then** 允许；其他普通目录与未绑定 Skill 拒绝。
2. **Given** 配置了存在的绝对业务目录，**When** 读取、编辑或写入其中的普通文件，**Then** 允许，目录外同名前缀路径拒绝。
3. **Given** 额外根覆盖公共 Skill 的祖先，**When** 读取未绑定 Skill 或写入任何公共 Skill，**Then** 拒绝；绑定 Skill 的读取仍允许。
4. **Given** 已授权业务目录，**When** 试图将它设为命令工作目录，**Then** 拒绝，工作目录仍限于当前 Agent。
5. **Given** 配置包含空白、相对、不存在或带原生链接的目录，**When** 启动，**Then** 以不泄露目标值的配置错误失败。

### User Story 2 - 越界请求在实际操作前拒绝 (Priority: P1)

Agent 发起文件、Shell、HTTP 或通知请求时，拒绝必须发生在真实操作前，并给出可理解的拒绝类别。

**Why this priority**: 直接验证白名单的执行效果，防止只有错误提示而危险操作已经发生。

**Independent Test**: 在本地临时文件、测试进程标记、HTTP 计数服务和通知发送桩上观测副作用。

**Acceptance Scenarios**:

1. **Given** 越界路径，**When** 读写/编辑/列举/搜索文件，**Then** 拒绝且目标内容、存在性不变，受保护内容不返回。
2. **Given** 未配置的命令 alias，**When** 执行 Shell 工具，**Then** 拒绝且进程启动次数为零；alias 大小写或前导空格不隐式变成授权命令。
3. **Given** 未授权域名、非法 URI 或形似子域名，**When** 调用 GET、POST 或通知，**Then** 拒绝且网络请求/发送次数为零。
4. **Given** 合法授权目标，**When** 调用工具，**Then** 使用获批准的目标成功执行一次；命令参数中的元字符保持字面值。
5. **Given** 空命令/域名白名单，**When** 请求对应能力，**Then** 默认拒绝；无额外文件根时仍保留故事 1 的内建权限。

### User Story 3 - 拒绝可追踪且不泄露秘密 (Priority: P2)

运维人员能从已有工具调用审计看到授权失败的可读原因，模型也得到同一个安全失败结果，且一次调用仅记录一次最终结果。

**Why this priority**: 确保安全拒绝自然接入现有运行链路，支持问题排查。

**Independent Test**: 通过真实工具执行链路及本地数据库审计，查询失败记录；不需要模型密钥或公网服务。

**Acceptance Scenarios**:

1. **Given** 当前 Agent 可见但目标越界的工具，**When** 经统一执行入口调用，**Then** 返回不可重试的失败，已有审计中恰好出现一条失败记录及可读拒绝原因。
2. **Given** 请求含预置凭证、Webhook 查询串或内部路径标记，**When** 拒绝，**Then** 错误和日志不含敏感目标；凭证与 Webhook 秘密不出现在审计中。
3. **Given** 使用同一授权策略的搜索及 MCP，**When** 配置或授权失败，**Then** 保持已有失败分类和默认拒绝行为。

### Edge Cases

- `..`、相邻同名前缀目录、原生软链接/Windows 目录链接、非法路径和不存在目标的最近存在父目录。
- 公共 Skill 根不存在、空绑定、无效绑定、公共根祖先被管理员授权；不得因解析失败回退为宽泛放行。
- 只列举/搜索宽泛额外根时，不得间接返回未绑定 Skill 文件名、元数据或内容。
- HTTP 根域与 `*.example.com`、`evil-example.com`、user-info、fragment、非法端口、非 HTTP(S) URI。
- 工具内部异常、超时和参数错误继续使用原有安全兜底，不将任意异常消息作为可信拒绝原因。
- 配置在启动时形成快照，运行中修改配置文件需重启生效。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 支持管理员配置额外普通文件目录，且只接受存在的绝对普通目录；拒绝空白、相对、不存在及包含原生链接的根，配置错误在启动时脱敏报告。
- **FR-002**: 系统 MUST 保留当前 Agent 目录可读写、绑定公共 Skill 只读及未绑定 Skill 不可见的权限；空额外根不得新增普通目录权限。
- **FR-003**: 管理员额外根 MUST NOT 覆盖公共 Skill 的保护语义；直接读取、列举、递归搜索及写入均不得绕过绑定和只读约束。
- **FR-004**: 文件校验 MUST 验证真实路径和不存在写入目标的最近存在父目录，拒绝路径穿越、链接及盘符/UNC 授权绕过；相对输入以当前 Agent 为基准。
- **FR-005**: 系统 MUST 对额外普通根允许读写，但不扩展 Shell 工作目录权限；文件执行方必须使用获批准的目标及已有写前复验。
- **FR-006**: 系统 MUST 保留受控命令 alias 与独立参数，精确匹配 alias，禁止整段命令输入；保留已有超时、输出和进程回收限制。
- **FR-007**: 系统 MUST 在 HTTP/通知外发前校验并使用同一个规范化批准目标，保留非法 URI 拒绝和域名标签边界；默认不跟随重定向。
- **FR-008**: 系统 MUST 将运行时 Sandbox 拒绝统一表达为可识别的拒绝，工具结果提供固定、安全的类别原因且不可重试；未知异常继续脱敏兜底。
- **FR-009**: 文件、Shell、HTTP、Notify MUST 对拒绝操作产生零次业务 IO；允许必要的授权校验 IO。edit_file MUST 在读取目标正文前通过 READ 与 WRITE 授权；授权成功仍按已有链路执行。
- **FR-010**: 系统 MUST 复用现有注册、可见性、执行、审计链路；拒绝调用恰好写一条最终失败审计，不新增专用审计写入通道。
- **FR-011**: 错误及日志 MUST NOT 输出敏感目标、命令参数、凭证或外部异常正文；安全拒绝原因不得拼接原始目标。审计输入与错误消息 MUST 分别脱敏，Shell arguments 中的凭证（含分离参数及 --key=value）和 Webhook 秘密不得明文入库。
- **FR-012**: 系统 MUST 保持既有 HTTP、Shell 配置与搜索/MCP 授权行为兼容；新增文件根为启动快照，并明确记录课件配置的映射。
- **FR-013**: 系统 MUST 提供成对允许/拒绝、绕过、四工具零 IO 和持久化审计的自动验证，并准确披露平台能力或外部依赖导致的未验证场景。

### Key Entities

- **授权配置快照**：启动时确认的额外目录、命令和域名集合。
- **文件访问边界**：当前 Agent、绑定 Skill、管理员普通根及对应权限。
- **批准目标**：校验后的唯一执行对象。
- **拒绝结果与调用审计**：安全拒绝类别和现有调用的最终持久化记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 额外根、Agent、绑定/未绑定 Skill 的允许与拒绝矩阵全部通过；所有拒绝写入用例的目标修改次数为零。
- **SC-002**: 文件、命令、HTTP、通知四组拒绝用例均能证明被拒绝的业务 IO 次数为零；edit_file 拒绝写权限时目标正文读取次数也必须为零。必要元数据校验不计入；授权调用不发生重复业务执行。
- **SC-003**: 一次越界调用返回不可重试失败，持久化失败记录恰好一条，原因与模型收到的安全失败一致。
- **SC-004**: 预置秘密在失败结果、日志、审计中明文出现次数为零；错误和日志中的敏感目标出现次数为零。
- **SC-005**: 原有四类工具、Skill 绑定、搜索和 MCP 的相关回归全部通过；因平台缺失未执行的场景逐项披露。

## Assumptions

- 管理员可信，配置通过现有本地配置渠道提供；无运行时管理 API 或热更新需求。
- 本功能是单进程应用层限制；解释器代码和恶意本地并发攻击不属于隔离承诺。
- 使用已有 Provider、Registry、ProfileContext、ToolExecutor 和数据库审计；不新增模块、表、公共 Profile 字段或依赖。
- 课件全部 10 页为教学范围，已确认设计与 005 为实现适配依据；本课不交付容器/microVM、SSO、多租户、白名单管理界面。
- 测试采用本地临时文件、安全测试进程和回环 HTTP 服务，真实外部模型/Webhook 不在自动验收内。
