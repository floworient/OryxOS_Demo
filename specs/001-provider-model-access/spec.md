## User Scenarios & Testing *(mandatory)*

### User Story 1 - 加载完整 Agent 运行配置 (Priority: P1)

开发者在工作区放入一个或多个 Agent 目录。系统从每个 `AGENT.md` 的配置部分派生完整运行配置并按 Agent 名称登记；单个 Agent 配置错误时，只隔离该 Agent，不影响其他合法 Agent。

**Why this priority**: Provider 的选择和参数来自 Agent 运行配置。如果配置来源、字段和失败隔离不稳定，后续模型路由与 ReAct 都没有可信输入。

**Independent Test**: 准备两个合法 Agent 和一个非法 Agent，加载后检查两个合法 Agent 均可按名称查询且字段完整，非法 Agent 有明确错误并且没有阻断其余 Agent。

**Acceptance Scenarios**:

1. **Given** 一个包含全部当前版字段的合法 Agent 定义，**When** 系统加载工作区，**Then** 派生配置包含名称、描述、身份、Provider、工具、MCP Server、Channel、调度、Bootstrap 和运行设置。
2. **Given** Agent 目录存在 `skills/` 软连接，**When** 系统派生 Profile，**Then** Skill 绑定不进入 Profile 字段，后续由上下文加载阶段独立解析。
3. **Given** 一个 Agent 定义包含已废弃的 `notify_channels` 或 `skills` 字段，**When** 系统校验该定义，**Then** 给出可诊断的非法字段错误，不静默维护第二份绑定关系。
4. **Given** 多个 Agent 中只有一个配置非法，**When** 系统完成加载，**Then** 其余合法 Agent 仍全部登记并可用。

---

### User Story 2 - 配置一个供应商并完成首次模型调用 (Priority: P1)

运营人员为系统配置一个模型供应商（唯一名称、模型名、凭据、可选服务地址），Agent 定义通过该名称引用供应商。开发者用一个固定 Prompt 发起一次单轮请求，拿到模型返回的文本响应。

**Why this priority**: 没有可用的模型调用，ReAct、Tool、Memory 和所有上层能力都无法运行。这是整个运行时底座的前置能力。

**Independent Test**: 只配置一个供应商和一个引用它的 Agent 定义，发起一次固定 Prompt 的单轮请求，检查返回文本非空且供应商、模型、token 用量与耗时等信息可获取。本阶段没有面向最终用户的命令入口，通过内部调用入口和自动化测试验证。

**Acceptance Scenarios**:

1. **Given** 一个供应商已配置合法名称、模型名和有效凭据，**When** 一个 Agent 引用该名称并发起单轮请求，**Then** 系统返回该供应商的模型响应，响应内容非空。
2. **Given** 请求成功完成，**When** 调用方读取本次调用的元信息，**Then** 能获得供应商名称、模型名、输入 token 数、输出 token 数与调用耗时。
3. **Given** 只有一个供应商可用，**When** 两个不同 Agent 先后引用该供应商发起请求，**Then** 两次请求都成功，且互不改变对方的模型或参数配置。

---

### User Story 3 - 多供应商并存且按名称精确路由 (Priority: P2)

运营人员同时配置两个及以上供应商。不同 Agent 分别声明不同供应商，系统按 Agent 声明的名称精确选择对应模型，不存在类型相同而无法区分的情况。

**Why this priority**: 企业通常同时使用云端与本地模型，多供应商并存是私有化部署的常见要求。路由错误会把数据发给错误的供应商，影响安全与成本。

**Independent Test**: 配置两个名称不同、模型也不同的供应商，让两个 Agent 分别引用；分别发起请求，验证每次响应来自声明的那一个供应商，且不会落到另一个供应商。

**Acceptance Scenarios**:

1. **Given** 两个供应商名称和模型均不同，**When** Agent A 引用供应商甲、Agent B 引用供应商乙，**Then** A 的请求只由甲完成，B 的请求只由乙完成。
2. **Given** 存在多个已配置供应商，**When** 查询已配置供应商清单，**Then** 清单按名称唯一列出全部供应商，不出现重复或遗漏。
3. **Given** 两个供应商被配置为相同名称，**When** 系统加载配置，**Then** 系统拒绝启动并明确报告重复的名称，不静默选择其中一个。

---

### User Story 4 - 配置与密钥错误可诊断、不泄露 (Priority: P2)

运营人员通过环境变量或独立本地配置提供凭据。配置缺失、格式错误或引用不存在的供应商时，系统在发起调用前给出可操作的错误信息，明确指出供应商、字段和原因；日志与对外输出中不出现凭据原文。

**Why this priority**: 配置错误是接入阶段最高频的故障；密钥泄露则是安全红线。错误必须早发现、可定位、可修复。

**Independent Test**: 分别构造缺失凭据、空凭据、未知供应商名称、非法服务地址四类配置，检查系统在首次调用前返回明确错误；扫描日志和输出，确认不含凭据内容。

**Acceptance Scenarios**:

1. **Given** 某个被 Agent 引用的供应商缺少必填凭据，**When** 系统启动并加载配置，**Then** 启动失败，错误信息指出供应商名称和缺失字段，且不发出任何对外请求。
2. **Given** 一个 Agent 引用了不存在的供应商名称，**When** 系统加载该 Agent，**Then** 该 Agent 被标记为不可用并给出明确原因，其他配置合法的 Agent 不受影响。
3. **Given** 凭据通过环境变量提供，**When** 系统输出日志、错误堆栈或状态信息，**Then** 任何位置都不出现凭据原文。
4. **Given** 凭据缺失或非法，**When** 请求发起，**Then** 系统不会改用其他已配置供应商完成请求。

---

### User Story 5 - 调用失败与工具意图不被静默处理 (Priority: P3)

供应商返回认证失败、限流、超时或网络错误时，调用方收到明确的失败结果，系统不假装成功、不自动切换供应商。模型返回工具调用意图时，系统不自行执行任何工具，而是把意图交给调用方处理，为后续 ReAct 能力保留正确边界。

**Why this priority**: 静默失败和重复执行工具会破坏审计与数据一致性。工具自动执行是本项目最容易写错、后果最严重的一条边界。

**Independent Test**: 用受控的供应商桩分别返回认证失败、超时和工具调用意图，检查失败被如实上报、没有发生供应商切换、没有任何工具被实际执行。

**Acceptance Scenarios**:

1. **Given** 供应商返回认证失败，**When** 请求完成，**Then** 调用方收到带供应商与模型标识的失败结果，系统中没有任何部分将其视为成功。
2. **Given** 供应商调用超时，**When** 连接或读取超过本阶段固定的 60 秒上限，**Then** 调用返回超时错误，不无限等待，也不重试到其他供应商。
3. **Given** 模型响应包含工具调用意图，**When** 系统处理该响应，**Then** 系统不执行任何工具，并把意图原样交给调用方决策。

---

### User Story 6 - 工具定义可被模型理解但不会被 Provider 执行 (Priority: P3)

开发者向一次模型请求提供当前 Agent 可见的工具定义。系统把工具名称、说明和参数约束转换为模型供应商可以理解的 Schema；Provider 只负责转换与传递，绝不执行工具。

**Why this priority**: ReAct 后续依赖模型正确产生工具调用意图，同时必须守住工具只能由统一执行器调度的边界。

**Independent Test**: 用一个包含必填参数、枚举和嵌套对象的受控工具定义执行转换，验证字段语义完整；再让模型返回工具意图，确认工具执行次数为零。

**Acceptance Scenarios**:

1. **Given** 一个合法工具定义，**When** 系统转换并随请求发送，**Then** 工具名称、说明、参数类型、必填项和约束保持一致。
2. **Given** 工具定义缺少名称或参数结构非法，**When** 系统转换，**Then** 在对外请求前返回明确错误，不发送残缺 Schema。
3. **Given** 模型根据 Schema 返回工具调用意图，**When** Provider 处理响应，**Then** 只返回结构化意图，工具执行次数为零。

---

### Edge Cases

- 供应商名称大小写或首尾空格不一致时，应视为不同名称还是同一个？默认按精确匹配处理，不做隐式归一化，并在错误信息中提示可能的拼写问题。
- 凭据配置为占位符（如 `${ENV_VAR}` 未被解析）时，应在启动校验阶段报错；不得把占位符当作真实凭据发送。
- 同一供应商被多个 Agent 并发引用时，各自的模型参数（如温度）互不干扰。
- 供应商返回空内容或只有空白字符时，应作为可疑结果上报，不视为成功响应。
- 供应商返回的 token 用量缺失时，调用仍可成功，但记录中必须标记用量未知。
- 服务地址非法或不可达时，错误信息应区分「配置格式错误」与「网络不可达」。
- 已配置但从未被任何 Agent 引用的供应商不应阻止系统启动。
- Agent 工作区不存在或为空时，应返回空注册结果而不是阻止进程启动。
- Agent 目录名与 frontmatter `name` 不一致时，该 Agent 必须加载失败并报告两个名称；Agent 名称必须等于目录名，不允许静默覆盖任一值。
- Agent 定义包含已废弃的 `skills` 或 `notify_channels` 字段时不得静默吞掉，避免课件旧字段重新成为隐式契约；其他扩展字段按当前技术方案的阶段规则处理。
- 工具参数 Schema 存在不支持或无法无损表达的结构时，应在调用模型前失败并指出工具与字段，不得自行降级约束。
- 模型调用已获得响应但审计记录持久化失败时，应向调用方报告审计失败，不得把本次调用报告为成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 运营人员 MUST 能声明一个或多个模型供应商；每个供应商 MUST 有唯一名称、模型名、凭据，以及可选的服务地址。供应商 MUST 由部署侧的应用级配置声明，不随业务工作区分发；Agent 定义 MUST NOT 能新增或改写供应商，只能按名称引用。
- **FR-002**: Agent 定义 MUST 能通过供应商名称引用供应商；系统 MUST 按名称显式解析到唯一供应商，不得按类型或注册顺序推断。
- **FR-003**: 系统 MUST 完成阿里云百炼（DashScope）的真实端到端调用，作为本阶段的验证基准供应商；并 MUST 支持采用 OpenAI 兼容协议的服务地址作为第二类接入方式。
- **FR-004**: 系统 MUST 支持单轮请求并返回模型文本响应；调用方 MUST 能获得供应商名称、模型名、输入/输出 token 数与调用耗时。
- **FR-005**: 系统 MUST 在加载配置时校验供应商名称唯一性与必填字段；重复名称 MUST 阻止启动并指明冲突的名称。
- **FR-006**: 当 Agent 引用未知供应商时，系统 MUST 将该 Agent 标记为不可用并给出原因，同时 MUST NOT 阻止其他合法 Agent 加载。
- **FR-007**: 凭据 MUST 仅从环境变量或独立本地配置加载；凭据 MUST NOT 出现在 Agent 定义、版本库、日志、错误输出或对外响应中。
- **FR-008**: 凭据缺失、未解析的占位符或格式非法时，系统 MUST 阻止调用，并指出供应商与具体字段。校验时机 MUST 为启动阶段：被任一 Agent 引用的供应商一旦凭据缺失或非法，启动 MUST 失败；未被引用的供应商只校验结构完整性，不影响启动。
- **FR-009**: 供应商调用失败（认证、限流、超时、网络错误）时，系统 MUST 向调用方返回明确失败结果；连接与读取超时在本阶段固定为 60 秒且不新增配置键；本阶段 MUST NOT 自动切换到其他供应商或静默重试。
- **FR-010**: 每次模型调用 MUST 产生一条可追溯的记录，包含供应商、模型、输入/输出/总 token 数（未知时显式标记）、耗时、结果状态与发生时间。记录 MUST 在本阶段即持久保存为 `llm_calls` 数据，进程退出后不丢失，不得只保留在内存中；若持久化失败，本次 Provider 调用 MUST 失败关闭并报告审计错误，不得向调用方返回成功结果。
- **FR-011**: 系统 MUST 禁止自动执行模型返回的工具调用意图；该类意图 MUST 原样交给调用方，为后续 Agent 循环保留统一执行边界。
- **FR-012**: 调用方的模型参数（如温度）MUST 按 Agent 配置生效，且并发请求之间 MUST NOT 相互污染。
- **FR-013**: 系统 MUST 扫描 `.oryxos/agents/<name>/AGENT.md`，从 frontmatter 派生当前版完整 Profile；字段 MUST 包含 `name`、`description`、`identity`、`provider`、`tools`、`mcp_servers`、`channels`、`schedules`、`bootstrap`、`settings`，且 MUST NOT 包含 `skills` 或 `notify_channels`。
- **FR-014**: 系统 MUST 独立校验每个 Agent 的定义；frontmatter `name` MUST 与目录名相等。单个 Agent 格式错误、名称不一致、引用未知 Provider 或包含已废弃字段时，MUST 记录该 Agent 的具体失败原因并继续加载其他 Agent。
- **FR-015**: 系统 MUST 提供按名称查询、列出全部和登记 Profile 的内存索引；同一加载批次出现重复 Agent 名称时 MUST 报错，不得按扫描顺序静默覆盖。
- **FR-016**: 系统 MUST 把当前 Agent 可见工具的名称、说明和输入参数约束无损转换为模型请求所需的工具 Schema；转换过程 MUST NOT 执行工具，也 MUST NOT 改变工具可见范围。
- **FR-017**: 工具定义缺少必填元数据、Schema 非法或无法无损表达时，系统 MUST 在发出模型请求前失败，并在错误中标识具体工具和字段。

### Key Entities

- **供应商配置（Provider）**: 一个可调用的模型服务定义，包含唯一名称、模型名、凭据引用和可选服务地址；是 Agent 引用模型的唯一依据。
- **凭据（Credential）**: 与供应商关联的秘密值，只能通过受控来源加载，不随配置实体明文保存。
- **Agent 定义（Agent Profile）**: 从 Agent 目录的 `AGENT.md` frontmatter 派生的完整运行配置，包含身份、Provider、工具、MCP、Channel、调度、Bootstrap 与运行限制；不承载 Skill 绑定或通知渠道注册。
- **Profile 索引（Profile Registry）**: 按 Agent 名称保存已成功派生 Profile 的内存索引；失败的 Agent 不进入可用集合。
- **工具 Schema（Tool Schema）**: 模型可见工具的声明性结构，包含名称、说明、参数类型、必填项和约束；它只描述能力，不代表执行授权。
- **调用记录（Model Call Record）**: 一次模型调用的元信息，用于成本透明与问题定位，包含供应商、模型、token 用量、耗时、结果状态和时间；持久保存，进程退出后仍可查询。
- **模型响应（Model Response）**: 供应商返回的文本内容、token 用量与可选的工具调用意图。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在仓库已检出、JDK 21/Maven Wrapper 可用且依赖已完成首次下载的前提下，熟悉文档的开发者按 Quickstart 从输入无密钥验证命令到完成「配置一个供应商 + 让一个 Agent 引用它 + 发起一次请求」闭环，实测耗时 MUST 不超过 300 秒。
- **SC-002**: 在配置两个及以上供应商的验证场景中，100% 的请求被路由到 Agent 声明的供应商，0 次跨供应商误投。
- **SC-003**: 100% 的配置错误（缺失凭据、未解析占位符、重复名称、未知供应商引用）在首次对外调用前被发现，并给出包含供应商名称和字段名的错误信息。
- **SC-004**: 对日志、错误输出和对外响应的检查中，凭据原文出现次数为 0。
- **SC-005**: 100% 的模型调用产生可追溯记录，记录中包含供应商、模型、耗时、结果状态与时间；token 用量缺失时显式标记为未知；记录在进程重启后仍可被查询到。
- **SC-006**: 在模型返回工具调用意图的验证场景中，工具实际执行次数为 0。
- **SC-007**: 不含模型自身响应时间，系统内部转发开销不超过 50 毫秒。
- **SC-008**: 在包含两个合法 Agent 和一个非法 Agent 的加载场景中，合法 Agent 加载成功率为 100%，非法 Agent 可用率为 0%，且错误能定位到 Agent 与字段。
- **SC-009**: 对课程规定的工具 Schema 样例进行转换时，名称、说明、参数类型、必填项和约束的保持率为 100%，工具实际执行次数为 0。

## Assumptions

- 本阶段没有面向最终用户的命令入口，验收通过内部调用入口、自动化测试和受控供应商桩完成；完成后与 ReAct 能力一起在后续场景中展示。
- 供应商凭据由部署环境通过环境变量提供，本地配置文件仅用于开发；不引入密钥管理服务或加密存储。
- 真实供应商端到端验证需要部署环境提供有效凭据与网络可达；缺少凭据或网络时，其余行为用受控供应商桩验证，并明确报告未验证项，不以模拟结果视为端到端通过。
- 默认支持 OpenAI 兼容协议；其他协议按供应商适配能力逐个接入，不在本阶段要求全覆盖。
- 核心阶段为单实例部署，不提供故障转移、备用供应商、熔断或对冲请求。
- 本阶段不实现流式响应、多轮对话、工具执行或上下文管理，这些由后续能力承接。
- 调用记录在本阶段必须产生、持久保存并可用于追溯；面向用户的审计查询界面可在后续阶段交付。
- 供应商名称按精确匹配处理，不做大小写或空白的隐式归一化。
- 已配置但未被引用的供应商不阻止启动；只要其自身配置合法即可保留。
- 本 feature 采用当前架构修订：Agent 目录而非独立 Profile YAML 是配置真相源；Skill 软连接和全局通知渠道不进入 Profile。
- 本 feature 完成完整 Profile 派生与工具 Schema 转换；002 仅复用这些能力，不再承担其首次定义。
- Tool Schema 由调用方在构造 `Prompt` 前通过本节的适配器加入请求选项；`ProviderService` 只保留 Schema 并强制关闭内部执行，不在本节提前引入 `ToolRegistry`。
