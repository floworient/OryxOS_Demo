# Feature Specification: 第一版 Web 对话工作台

**Feature Directory**: `specs/010-web-chat-console`

**Created**: 2026-11-06

**Status**: Draft（依据已提交设计文档，待评审确认）

**Input**: 用户要求「使用 speckit 完成第一版工作台」；设计来源为 `docs/superpowers/specs/2026-11-06-oryxos-web-chat-frontend-design.md`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 演示者完成一次真实 Agent 对话并看到工具调用 (Priority: P1)

演示者在浏览器中打开工作台，左栏看到运行时真实注册的 Agent，选择「每日天气」并提问。消息经运行时统一链路处理后返回真实模型回复，回复下方展示本轮实际执行的工具名称。整个过程不需要 curl、Swagger UI 或任何脚本。

**Why this priority**: 这是本版工作台存在的唯一核心理由：让观众在一屏内同时看到「Agent 是运行时真注册的」「回复是模型真跑的」「工具是真调用的」。没有这条链路，其余界面能力都没有演示价值。

**Independent Test**: 在已配置 Provider 与 `daily-weather` Agent 的环境中打开页面，确认左栏 Agent 数量与运行时接口返回一致；发送一条天气问题，确认回复来自模型且该轮工具标记与后端会话历史中的工具调用一致。

**Acceptance Scenarios**:

1. **Given** 运行时正常启动且工作区存在至少一个 Agent，**When** 打开工作台，**Then** 左栏展示运行时返回的全部 Agent，默认选中第一个，顶部显示运行状态与 Provider 名称。
2. **Given** 已选中 `daily-weather` 且没有进行中的请求，**When** 输入问题并发送，**Then** 页面出现用户消息、等待状态，随后展示真实模型回复。
3. **Given** 一轮对话执行了工具调用，**When** 回复到达，**Then** 该轮回复下方展示工具名称，且工具名称集合与后端会话历史一致。
4. **Given** 运行时没有配置任何 Agent，**When** 打开工作台，**Then** 展示如何创建工作区 Agent 的引导，而不是空白页或报错。
5. **Given** 用户输入为空或仅含空白字符，**When** 尝试发送，**Then** 不发起请求，并在输入区提示消息不能为空。

---

### User Story 2 - 刷新或切换 Agent 后会话仍然延续且互不串扰 (Priority: P2)

演示者刷新浏览器后，当前 Agent 的历史消息仍在，继续提问能接上前文；切换到另一个 Agent 时看到它自己的会话，不会混入前一个 Agent 的消息。演示者也可以主动开始新对话或归档当前会话。

**Why this priority**: 运行时的核心承诺之一是 Session 可恢复。工作台必须证明会话不是页面内存里的假历史，而是可跨刷新恢复的真实运行时状态。

**Independent Test**: 与一个 Agent 完成两轮对话后刷新页面，确认两轮历史都恢复且第三轮能延续上下文；再切换到另一个 Agent，确认消息列表独立；点击「新对话」后确认下一条消息创建新会话。

**Acceptance Scenarios**:

1. **Given** 当前 Agent 已有一轮或多轮历史，**When** 刷新浏览器，**Then** 该 Agent 的历史消息与工具标记重新展示，且可继续发送消息。
2. **Given** Agent A 有历史而 Agent B 没有，**When** 从 A 切换到 B，**Then** 页面只展示 B 自己的会话内容，不出现 A 的消息。
3. **Given** 当前会话已有历史，**When** 点击「新对话」，**Then** 当前活动会话被归档（不物理删除），页面清空为欢迎状态，下一条消息创建新的会话。
4. **Given** 当前会话已有历史，**When** 归档会话，**Then** 页面回到空对话状态，下一条消息创建新会话。
5. **Given** 浏览器本地保存了某个会话标识但该会话在运行时已不可用，**When** 页面加载，**Then** 给出明确提示并允许开始新对话，不持续报错或白屏。

---

### User Story 3 - 故障时得到明确、可操作的状态反馈 (Priority: P3)

后端未启动、模型服务不可用、上一轮仍在执行或调用超时时，工作台给出中文化、可理解的状态提示，保留用户尚未成功发送的输入，并提供重试路径，而不是静默失败、卡死或白屏。

**Why this priority**: 演示环境经常出现网络或密钥问题。把底层错误码翻译成明确提示，能避免演示中断时无法判断问题所在，也保护「不做假数据」的交付真实性。

**Independent Test**: 分别模拟后端不可达、模型服务不可用、会话忙碌和调用超时，确认界面在每种情况下都显示对应中文提示且不丢失用户输入。

**Acceptance Scenarios**:

1. **Given** 后端未启动或网络不可达，**When** 打开页面或发送消息，**Then** 页面显示「无法连接运行时」类提示，不白屏。
2. **Given** 模型 Provider 不可用，**When** 发送消息，**Then** 页面提示检查 Provider 配置，并允许重试。
3. **Given** 上一轮消息仍在执行，**When** 用户尝试再次发送，**Then** 发送入口保持禁用，页面提示上一轮尚未结束。
4. **Given** 单轮调用超过运行时上限，**When** 等待状态结束，**Then** 页面提示本轮已超时，并保留可重试的输入。
5. **Given** 请求进行中，**When** 等待超过约定提示时间，**Then** 气泡内持续显示已等待时长，接近上限时给出即将超时提示。

### Edge Cases

- 工作区没有 Agent、Agent 列表加载失败、Agent 在选中后从运行时移除。
- 后端不可达、跨域或代理配置错误、响应格式异常。
- 用户消息只含空白、超长消息被运行时拒绝。
- 用户快速重复点击发送、在等待期间切换 Agent 或刷新页面。
- 会话已被归档或被其他人归档后继续发送。
- 历史超过运行时单次返回上限而出现截断。
- 工具调用存在但没有可展示的参数或结果（本版只展示工具名称）。
- 浏览器禁用本地存储或处于隐私模式，导致会话标识无法保存。
- 运行时返回的错误码不在已知映射表中。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 工作台 MUST 在首屏从运行时动态获取并展示 Agent 列表，不得内置硬编码或示例 Agent 冒充真实注册结果。
- **FR-002**: 工作台 MUST 同时展示运行时状态摘要，至少包含可用状态、Agent 数量、Tool 数量与已配置 Provider 名称。
- **FR-003**: 工作台 MUST 默认选中列表中的第一个 Agent，并允许用户切换；同一 Agent 的会话状态 MUST 与其他 Agent 隔离。
- **FR-004**: 工作台 MUST 拒绝发送去除首尾空白后为空的消息，并在输入区域给出提示且不发起请求。
- **FR-005**: 用户在一个 Agent 下首次发送消息时，工作台 MUST 自动建立会话；后续消息 MUST 复用该会话；用户发起新对话后，下一条消息 MUST 建立新会话。
- **FR-006**: 所有用户消息 MUST 经运行时对外接口进入统一 Agent 执行链路；界面展示的回复 MUST 来自运行时真实返回，不得使用写死的假回复或占位数据。
- **FR-007**: 每轮回复完成后，工作台 MUST 展示该轮实际执行的工具名称集合，并与运行时会话历史中的工具调用保持一致；本版 MUST NOT 展示工具参数或返回结果。
- **FR-008**: 工作台 MUST 在页面刷新后恢复当前 Agent 的会话历史（含工具标记），并允许在该会话上继续对话。
- **FR-009**: 工作台 MUST 为每个 Agent 独立保存其当前会话标识；切换 Agent MUST 恢复各自的会话，不得串会话。
- **FR-010**: 工作台 MUST 提供「新对话」操作：若当前存在活动会话，先结束该会话（归档，不物理删除），再清空视图并丢弃本地会话标识，确保下一条消息创建真正的新会话而不是复用旧活动会话。
- **FR-011**: 工作台 MUST 提供归档当前会话的操作；归档成功后界面 MUST 回到空对话状态，下一条消息 MUST 创建新会话。
- **FR-012**: 等待模型回复期间，工作台 MUST 展示已等待时长并使发送入口不可重复提交，避免重复请求或会话忙碌冲突。
- **FR-013**: 工作台 MUST 将后端错误映射为面向用户的中文提示，至少覆盖：参数无效、Agent 不存在、会话忙碌、Provider 不可用、调用超时、存储或内部错误；失败后 MUST 保留用户输入并允许重试。
- **FR-014**: 后端不可达或响应不可解析时，工作台 MUST 展示明确的连接错误状态，不得白屏、静默失败或展示虚构内容。
- **FR-015**: 工作区没有可用 Agent 时，工作台 MUST 展示创建工作区 Agent 的引导，而不是空白页。
- **FR-016**: 工作台 MUST NOT 修改或扩展后端已冻结的接口契约，本版不新增后端 API。
- **FR-017**: 工作台 MUST NOT 在前端代码、浏览器存储、示例配置或仓库中保存真实模型密钥。
- **FR-018**: 本版 MUST NOT 包含认证、多用户与权限、流式输出、Provider/Agent 在线管理、调度管理、审计查询或通知渠道管理；这些能力不得在界面或文档中被描述为已经具备。
- **FR-019**: 工作台 MUST 明确区分「正在加载」「等待回复」「已失败」「已超时」状态，用户在任何状态下都能判断当前发生了什么。
- **FR-020**: 会话历史被运行时截断时，工作台 MUST 以不误导的方式呈现，不得暗示已展示完整历史。

### Key Entities

- **Agent 摘要**: 运行时注册的业务 Agent 的公开信息，包括名称、描述、所用模型与可见工具。
- **会话历史**: 某个 Agent 下当前会话的完整可展示消息序列，包括用户消息、助手回复及每轮工具调用名称。
- **会话标识**: 使浏览器在刷新后重新关联同一运行时会话的本地引用，按 Agent 区分。
- **运行时状态摘要**: 当前可用性、Agent 数、Tool 数与 Provider 名称的只读快照。
- **界面错误状态**: 由后端业务码或连接失败映射得到的用户可读提示，包含可重试性判断。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 演示者从打开页面到看到第一条真实回复，操作步骤不超过 3 步（选 Agent、输入、发送），其中默认 Agent 可省去选择步骤。
- **SC-002**: 页面首次加载展示的 Agent 数量与运行时接口返回数量 100% 一致，且名称集合完全相同。
- **SC-003**: 刷新页面后展示的历史消息数量与运行时返回的当前会话历史一致；继续发送的消息能关联到同一会话（会话标识不变）。
- **SC-004**: 在参数无效、Agent 不存在、会话忙碌、Provider 不可用、调用超时、后端不可达六种场景下，界面均展示可读中文提示，白屏或静默失败次数为 0。
- **SC-005**: 存在工具调用的轮次中，界面展示的工具名称集合与运行时会话历史中的工具调用 100% 一致。
- **SC-006**: 在至少 2 个 Agent 之间来回切换 10 次后，消息错放到其他 Agent 的次数为 0。
- **SC-007**: 仓库与浏览器存储中出现的真实模型密钥数量为 0。
- **SC-008**: 后端停止运行后，页面在 5 秒内给出明确的连接失败提示。
- **SC-009**: 本轮交付结束时，附一份可复现的验证记录，覆盖上述场景，并明确列出缺失密钥或未验证的部分。

## Assumptions

- 第一版工作台指「对话工作台」，范围依据 `docs/superpowers/specs/2026-11-06-oryxos-web-chat-frontend-design.md`；管理台、在线配置与治理页面不在本版范围。
- 后端以 009 已交付并冻结的 Web API 为准，不修改接口契约。
- 运行时不提供流式输出和会话列表，因此工作台采用同步请求与按 Agent 本地保存会话标识的方式实现会话延续。
- 运行时不提供认证与多用户能力，工作台只部署在可信内网演示环境。
- 演示 Agent 使用 `daily-weather`，天气数据源免密钥；模型 Provider 由部署方在运行时配置中提供。
- 目标浏览器为现代桌面浏览器（Chromium/Edge 近期版本）；本版不承诺移动端适配、国际化或暗色主题。
- 工作台是独立前端工程，开发时通过同源代理访问运行时，生产构建产物可作为运行时静态资源提供；具体工程化方式在计划阶段确定。
- 用户提供的 PDF 附件无法被解析；若其内容与本 spec 依据的设计文档不同，需要用户补充说明后再调整范围。

## Dependencies

- 依赖 009 已交付的运行时接口：Agent 列表、健康与运行信息、会话创建、消息发送、会话历史、会话归档。
- 依赖运行时完成 Provider 配置且模型服务可用；缺少密钥或网络时相关端到端场景标记为未验证。
- 依赖工作区存在可演示的 Agent 定义（`daily-weather`）。
- 不依赖企业 IM、通知渠道、真实第三方业务系统或公网服务。
