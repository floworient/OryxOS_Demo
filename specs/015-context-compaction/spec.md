# 功能规范：会话上下文压缩

**编号**：015-context-compaction

**日期**：2026-11-10

**状态**：草案，待评审

## 用户场景与验收

### US1 · 长会话控制输入量（P1）

运营者希望长会话和多步工具任务的模型输入保持有界。用可控模型和大体积工具响应独立验收。

1. 会话超过配置的轮数或历史预算时，主请求只携带预算内最新的完整历史轮次。
2. 本轮工具返回超大结果时，模型只收到带裁剪标记的有界结果，仍能将其与原工具调用对应。查询历史仍能获得原始结果。
3. 完整系统指令、核心记忆和当前用户输入等必需内容仍超出预算时，当前模型请求不发出，调用者收到可识别的超限错误。

### US2 · 保留早期上下文（P1）

会话用户希望继续使用早期决策、约束和未完成事项。用可控摘要模型与跨重启会话独立验收。

1. 完整旧轮次越出窗口时，主请求立即移除这些原文。待摘要的历史达到配置的最小批量后，主请求携带新增摘要。摘要模型只收到已有摘要和新增旧轮次。
2. 同一轮内重复请求模型、无新增越界轮次或重启后重新读取已保存的摘要时，已覆盖的原文不再次进入摘要请求。
3. 摘要模型不可用或返回无效内容时，主调用继续使用近期窗口和可用旧摘要。摘要覆盖位置保持在上次成功的位置。

### US3 · 稳定模型请求前缀（P2）

运营者希望在多次请求间复用稳定指令，降低动态内容过早变化造成的缓存损失。捕获模型请求验证。

1. 只改变时间、长期记忆、摘要或会话内容时，稳定指令前缀与工具定义的顺序保持一致，变化从动态区开始。
2. 修改 Agent 指令、Bootstrap 或可见 Skill 后，后续构建读取最新定义。时间随本轮触发更新，当前用户请求以及对应的工具往返保留原有角色和顺序。

### 边界

- 既有会话没有摘要也能继续使用。扩大窗口时，已摘要范围与重新纳入的历史应避免同时注入。
- 旧历史中没有正常结束的轮次保留原文。越界后可跳过该轮，继续处理后续完整轮次。
- 大量旧轮次积压时，单次摘要输入仍有界。未覆盖的历史保留可查，并可由后续用户轮次逐步追赶。
- 取消、无效摘要、模型超时及审计写入失败有不同处理路径。取消后停止处理，审计写入失败沿用运行时显式错误。

## 功能需求

- **FR-001** 统一运行时按轮数和输入预算选取连续的近期历史。当前用户输入及本轮工具消息的对应关系完整保留。
- **FR-002** 长工具结果的裁剪只发生在模型输入副本。原始 Session 和审计可按原方式查询。
- **FR-003** 在主请求和摘要请求发送前分别执行输入预算检查。不可压缩的必需内容超限时显式失败。预算估算与供应商实际用量分别报告。
- **FR-004** 摘要只提炼完整的历史轮次，保存摘要正文及处理位置。摘要输出的长度有上限。摘要属于单一会话，其内容视为历史数据。
- **FR-005** 摘要按新增越界历史分批推进。未达到最小批量时不发摘要请求，也不把待摘要原文塞回窗口。每个用户轮次最多尝试一次。普通失败保留上次已保存的摘要并继续，取消与审计异常沿用运行时约束。
- **FR-006** 支持为摘要显式配置独立模型。未配置时使用 Agent 当前模型。摘要调用使用统一模型审计，能与主调用区分，且不执行工具。
- **FR-007** 稳定 Agent 指令、Bootstrap、已绑定 Skill 元数据位于动态内容之前。工具定义保持稳定顺序及结构化协议。核心记忆全量提供，归档记忆按既有分区规则处理。
- **FR-008** CLI、HTTP 和定时入口复用同一上下文策略，Session 恢复后仍可读取原始消息和摘要。验收不依赖真实密钥。

### 关键数据

- **原始会话**：完整、可查询的用户、助手及工具消息。
- **滚动摘要**：指定会话早期轮次的有界派生记录及其覆盖位置。
- **模型输入视图**：稳定区和动态区组成的单次请求。可裁剪结果只存在于该视图中。

## 成功标准

- **SC-001** 在至少 30 个用户轮次且含超大工具结果的可控会话中，发出的每个模型请求都通过对应的输入预算检查，原始消息无损可查。
- **SC-002** 在正常滚动、服务重启和摘要失败三个验收场景中，已持久化摘要覆盖的原文重复送审次数为 0。
- **SC-003** 仅改变动态内容的请求对比中，稳定消息前缀字节完全一致。含多工具调用的请求中，调用和结果的对应错误及重复工具执行次数均为 0。
- **SC-004** 固定长会话样本的模型累计输入量和估算总费用均低于当前仅按轮数截断的基线。两组使用相同主模型、同一费率表和统一的全未命中假设，计入主调用与摘要调用的输入和输出。记录请求次数、摘要开销及计算口径。真实缓存命中和账单另行测量。

## 假设和范围

- 摘要会压缩早期细节，完整历史继续作为追溯依据。验收使用包含决策、约束及待办的固定样本。
- 输入预算优先于摘要的即时性。低频短会话可能尚未触发摘要，此时近期窗口照常工作。
- 摘要复用与重复请求验收基于同一会话串行写入。多进程同时写同一会话的协调沿用现有运行约束。
- 独立摘要模型由部署方显式选择。第三方客户端的上下文策略和共享 Key 使用情况属于其他工作。
