# 运行契约：上下文预算与摘要

## 部署配置

部署级前缀为 `oryxos.context`。兼容现有 Agent frontmatter 的 `settings.max_history_turns` 默认 20，含当前轮。

| 键 | 默认 | 校验或语义 |
| --- | ---: | --- |
| `main-input-budget` | 8192 | 估算输入上限，正整数 |
| `main-max-output-tokens` | 2048 | 主请求最大输出，正整数 |
| `summary-input-budget` | 4096 | 摘要输入上限，正整数且小于主预算 |
| `summary-max-output-tokens` | 384 | 摘要请求最大输出，正整数 |
| `summary-text-bytes` | 768 | 已存摘要正文上限，至少 128 且小于摘要输入上限 |
| `archival-text-bytes` | 1024 | 主请求中归档记忆正文的上限，非负且小于主预算 |
| `tool-result-bytes` | 2048 | 单个工具结果发送副本上限，至少 128 且小于主预算 |
| `summary-trigger-turns` | 4 | 待摘要完整轮数，正整数 |
| `summary-trigger-units` | 2048 | 待摘要原文估算阈值，正整数且不超过摘要输入上限 |
| `summary-provider`、`summary-model` | 未配置 | 同时填写或同时省略。省略时使用当前 Agent 的 Provider 和模型 |

部署方按实际模型窗口调低输入与输出配额，使两者之和留在模型窗口内。启动校验组合配额，并沿用现有 Provider 注册和显式解析。已配置的独立路由运行失败时进入普通摘要降级。

## 输入视图

输入估算单位为文本 UTF-8 字节数与协议余量之和。计入系统、用户、助手、工具消息文本、角色、工具 ID、名称、调用参数、schema 与描述。请求固定余量 128，每条消息 32，每条工具调用、响应和定义各 32。按构建后的内容计量，使用 long 累加。

稳定区在第一条系统消息。工具定义按工具名排序。动态区承载记忆、摘要、近期历史和本轮。当前时间使用同一次处理捕获的时区时间，仅添加到发送副本的当前用户消息。历史或摘要中的标签按历史数据转义。

1. 必需内容优先，包括完整指令、工具定义、完整核心记忆、原始当前输入和本轮工具消息骨架。当前工具结果优先保留最新结果内容。裁剪时按 Unicode 码点缩减，发送合法 JSON 并携带 `truncated: true`。预算仍不足时使用只包含状态和裁剪标记的最小对象。
2. 从剩余预算预留摘要区，再按有界归档记忆和最近完整轮次填充。扩大窗口时按排他游标判定摘要是否重叠。无可用空间时先省略归档或摘要，最终请求必须通过预算。
3. 摘要只收到上次摘要及新增合格历史，不附工具定义。使用同一估算方式对摘要请求设限。摘要需非空、无工具调用且不超过正文上限，才更新派生状态。

## 超限及失败

- 主请求必需内容超限抛出 `ContextBudgetExceededException`。HTTP 422 走统一 `ApiResponse`，`code=CONTEXT_BUDGET_EXCEEDED`。CLI 沿用失败路径，文本为“模型输入超过上下文预算”。调度记录失败执行。
- 普通摘要调用失败沿用旧摘要及已裁剪的近期窗口。审计写入失败和取消走原有错误处理。因主请求超限拒绝发送时，不补发摘要。
