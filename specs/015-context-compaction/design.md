# 设计稿：有界滑动窗口与持久化滚动摘要

依据项目宪章、《需求分析》的会话上下文流程、《技术方案》§4 的运行时及 §5 的记忆契约，以及《AI 编程指南》的规范评审顺序。项目定位沿用《行业调研》中的统一运行时。

## 方案取舍

- **已选择：持久化增量摘要。** 使用完整历史计算窗口，摘要只消化新增越界轮次。以派生状态持久化换取跨重启复用。
- **构建请求时临时摘要。** 不保存派生状态，同一历史在反复调用或重启后会重复计费。
- **规则裁剪。** 无摘要模型费用，适合处理过大的工具结果，难以可靠提取跨轮决策与未完成事项。

## 请求布局

稳定系统消息由 `ContextLoader` 当次读取并组装，包含 Agent 指令、Bootstrap 和已绑定 Skill 元数据。按工具名稳定排序的 schema 仍通过 Function Calling 字段发送。后续消息依次为带明确边界的长期记忆和可用摘要、近期历史、带本轮时间的当前用户输入、本轮助手工具调用与对应工具结果。时间固定于一次 Agent 处理开始时，在发送副本的当前用户消息中添加运行时标签，保留原始用户文本。工具调用及结果使用结构化消息，避免在两者之间插入其他消息。

缓存前缀验收覆盖现有支持的模型请求序列化路径。对比时固定 Agent 与工具配置。工具定义与 Agent 正文合法变更后，允许重新形成前缀。

## 窗口和预算

- 保留现有 `max_history_turns` 默认 20 的语义，当前轮计入上限。轮次从用户消息开始，本轮之前的轮次以最终助手回复结束且工具调用均有匹配结果才可用于摘要。
- 先保留必需内容和当前轮。依预算裁剪工具返回的发送副本，使用含裁剪标记的合法数据并保留工具调用 ID。随后从近期向早期纳入连续完整轮次。归档记忆与摘要有独立配额，核心记忆全量提供。
- 对系统与用户文本、结构化工具参数、结果、工具 schema 及消息封装估算输入量。主请求和摘要请求分别检查，超限时不得发送。首版使用保守的本地估算，输出预留与模型窗口配置在实施计划中定值。验收同时比较相同样本的累计输入量，区分估算与供应商实测。

## 摘要与会话状态

- 状态由摘要正文和已处理历史的消息排他结束下标组成，下标位于轮次边界。可恢复但没有正常结束的旧轮可以在扫描时跳过，摘要输入只包含完整轮次。保留原始消息，用同一次 Session 更新保存成功摘要及游标。旧记录默认无摘要。新增数据库字段通过当前支持的数据库迁移维护。跨重启复用基于同一会话串行写入。
- 每个用户轮次最多在首次主调用前请求一次摘要。构建窗口时预留摘要区配额，避免摘要长度变化反过来移动窗口边界。摘要输入为上一摘要和从游标开始、截至窗口外的有界连续完整轮次。后续 ReAct 请求因工具结果增长而新移出的轮次在下一用户轮次处理。积压超预算时只推进此次实际覆盖范围，单个过大旧轮在摘要输入副本中带标记缩减，避免游标永久停滞。
- 摘要按配置的最小批量触发。低于阈值时立即应用窗口，累计待摘要范围到后续轮次再处理。实施计划需设定默认触发阈值、摘要输入和输出配额，并用固定样本核算包含摘要在内的总输入及输出开销。
- 窗口扩大而与摘要覆盖范围重叠时，当次省略摘要，保留已保存状态。后续边界重新达到游标时恢复注入，并对新增越界轮次继续摘要。
- 摘要调用经现有 Provider 路由和审计，标记调用用途并记录实际 Provider、模型和用量。独立模型由配置显式授权，缺省使用 Agent 主模型。摘要提示只包含摘要任务指令和有界历史数据，禁用工具，拒绝含工具调用、空白或超限输出的结果。
- 普通摘要失败不推进游标，也不在同轮重试。主请求以仍适用的旧摘要和近期窗口继续。取消与审计写入错误显式传播。会话保存沿用成功路径，若摘要成功后整个会话未保存，下一次处理可能重新摘要尚未持久化的范围。

## 验证重点

用可控 Provider 和临时持久化存储测试多工具消息配对、按预算缩窗、摘要失败与重启恢复。主模型和摘要模型分别记录请求大小及用途，以相同历史比较改造前后的总输入。实现计划需覆盖 Spring AI 序列化边界和数据库迁移，并落实错误映射及请求配置。
