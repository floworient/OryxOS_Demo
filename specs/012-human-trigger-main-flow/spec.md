# Feature Specification: 人推 Agent 主流程串联

**Feature Directory**: `012-human-trigger-main-flow`

**Created**: 2026-11-06

**Status**: Draft

**Input**: 用户要求依据第 27 节课件，使用 Spec-Kit 打通从 CLI 或 REST 进入的一次完整 Agent 对话，并对会话、模型调用、工具调用、记忆和管理台视图进行可重复对账。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 无密钥验证完整 Agent 主流程 (Priority: P1)

维护者无需配置真实模型密钥或访问公网，即可发起一轮确定性的 Agent 对话。该对话必须真实经过统一 Agent 执行入口、提示组装、两轮模型决策、一次记忆工具调用、工具结果回填、会话保存和审计记录，从而证明各模块之间的交接能够工作。

**Why this priority**: 本节目标不是新增孤立能力，而是证明现有能力能组成一条可信、可重复、可进入构建门禁的主流程。

**Independent Test**: 在临时工作区和临时数据库中，选择无密钥测试 Provider 发出一条“记住……”消息；随后只通过公开查询能力及持久化记录核对回复、会话、记忆和两类审计数据。

**Acceptance Scenarios**:

1. **Given** 一个只允许 `save_memory` 的测试 Agent，**When** 用户发送一条“记住：我喜欢喝美式咖啡”消息，**Then** 系统执行两轮模型调用、恰好一次 `save_memory`，并返回非空最终回复。
2. **Given** 上述对话已经完成，**When** 维护者读取会话历史，**Then** 历史按顺序包含用户消息、带工具请求的模型消息、工具结果和最终模型回复。
3. **Given** 上述对话已经完成，**When** 维护者核对持久化痕迹，**Then** 同一会话关联恰好两条成功模型调用和一条成功工具调用，且长期记忆中能立即读取刚写入的事实。
4. **Given** 同一构建重复执行该场景，**When** 不提供任何真实模型密钥或公网访问，**Then** 结果保持确定且不会退化为绕过真实 ReAct、Tool、Memory、Session 或审计链路的伪测试。

---

### User Story 2 - 通过 REST 与管理台对账会话 (Priority: P1)

运维人员可以列出最近会话，按最后活跃时间查看摘要并打开既有详情接口提供的最近 100 条受限历史；管理台使用同一公开数据展示这些会话，因此 REST 与管理台看到的是同一份运行时事实。

**Why this priority**: 缺少会话列表时，主流程留下的记录无法被发现，管理台也只能依赖浏览器本地保存的会话标识，不能完成“三面同源”对账。

**Independent Test**: 预置不同渠道、状态和时间的会话，通过 `GET /api/v1/sessions` 查询，再在管理台选择一条会话并核对其详情。

**Acceptance Scenarios**:

1. **Given** 系统中存在多个活动和归档会话，**When** 调用 `GET /api/v1/sessions`，**Then** 默认返回最近 100 条摘要，按最后活跃时间倒序且同时间时顺序稳定。
2. **Given** 会话数量超过 100，**When** 查询默认列表，**Then** 只返回 100 条且不携带完整消息正文。
3. **Given** 调用方指定 `status=active`，**When** 查询会话列表，**Then** 只返回活动会话；未知状态值被明确拒绝。
4. **Given** 一次 CLI、REST、调度或内部调用留下了会话，**When** 查询会话列表，**Then** 摘要包含会话标识、Agent、渠道、用户、状态、创建时间、最后活跃时间和消息数量，并能继续查询该会话详情。
5. **Given** 管理台已打开会话视图，**When** 后端存在真实会话，**Then** 页面展示真实列表、加载状态、空状态和失败重试，不用模拟数据或仅靠浏览器本地标识生成列表。

### User Story 3 - 从不同人推入口复用同一引擎 (Priority: P2)

开发者可以分别从 CLI 和 REST 发起 Agent 对话，并确认两种入口都进入同一 Agent 处理链路、使用同一持久化与审计语义，而不是各自复制一套执行逻辑。

**Why this priority**: OryxOS 的核心价值之一是多入口共享运行时；只证明单个入口可用，无法发现入口与内核之间的接缝问题。

**Independent Test**: 使用可控 Provider，分别经 CLI 与 REST 完成一轮包含工具调用的对话，按各自会话标识核对消息与审计结构一致。

**Acceptance Scenarios**:

1. **Given** 同一个 Agent 可被 CLI 与 REST 调用，**When** 两个入口分别完成同样的确定性对话，**Then** 两次对话都遵循相同的两轮模型、一次工具调用和消息累积语义。
2. **Given** 任一入口完成对话，**When** 通过公开会话详情查询该记录，**Then** 能读取同一持久化来源中的完整受限历史。
3. **Given** 模型请求包含工具意图，**When** 主流程运行，**Then** 工具只由统一工具执行器执行一次，不因框架自动工具执行而重复。

---

### User Story 4 - 失败路径仍可审计且不拖垮进程 (Priority: P2)

维护者可以确定模型失败、安全策略拒绝和工具异常均留下失败审计记录，并且单次失败不会让运行时进程不可继续服务。

**Why this priority**: 成功路径通常已有局部测试；串联阶段最容易遗漏的是模块交接处的失败记录和错误传播。

**Independent Test**: 分别制造 Provider 失败、Sandbox 拒绝和工具执行异常，核对对应审计记录和后续健康请求。

**Acceptance Scenarios**:

1. **Given** Provider 调用失败，**When** 对话结束于错误，**Then** 该次模型调用关联原会话并记录失败状态，错误响应不泄露密钥或内部地址。
2. **Given** Sandbox 拒绝一次工具动作，**When** 工具调用被阻止，**Then** 只产生一条失败工具审计，实际副作用没有发生。
3. **Given** 工具执行时抛出异常，**When** 执行器返回失败，**Then** 失败工具审计完整记录且运行时仍能处理后续无关请求。

### Edge Cases

- 会话列表为空时返回空集合，管理台显示明确空状态，不把空数据当成故障。
- 多个会话具有相同最后活跃时间时，列表顺序必须稳定，避免翻页或刷新时抖动。
- `status` 为空白、大小写不同或不是支持值时，不得静默返回误导性全集。
- 会话摘要必须避免携带消息正文、工具参数、工具结果、提示词、凭证或内部路径。
- 无密钥测试 Provider 只能由显式配置选择；不得成为未配置 Provider 时的静默回退。
- 无密钥测试的脚本状态必须按会话隔离，并能应对构建中多个测试顺序变化。
- 主流程执行到一半失败时，已发生的审计记录必须保留；不得声称回滚已经完成的外部副作用。
- 工作区缺少 Agent 定义、显式引用的 Bootstrap 或绑定 Skill 时，应给出可定位的加载失败或告警，不得悄悄改变 Agent 行为。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个显式选择、无需密钥和公网的确定性测试 Provider，用于驱动包含一次工具调用的两轮 Agent 对话。
- **FR-002**: 测试 Provider MUST 只替代模型响应；AgentService、提示组装、ReAct 循环、工具执行、记忆、Session 和审计 MUST 使用正式运行路径。
- **FR-003**: 测试 Provider MUST 按会话隔离交互状态，第一轮请求一次 `save_memory`，收到匹配工具结果后的第二轮返回最终答复；异常输入 MUST 明确失败而非猜测继续。
- **FR-004**: 测试 Provider MUST 通过名称显式映射并由 Agent 明确引用，不得作为真实 Provider 失败时的 fallback。
- **FR-005**: `GET /api/v1/sessions` MUST 返回会话摘要列表，并继续使用统一成功或错误响应信封。
- **FR-006**: 会话列表 MUST 默认最多返回最近 100 条，按 `lastActiveAt` 倒序、会话标识升序形成稳定次序。
- **FR-007**: 会话列表 MUST 支持可选 `status=active` 过滤；不支持的状态 MUST 返回稳定的参数校验错误。
- **FR-008**: 每条会话摘要 MUST 包含会话标识、Agent 名称、渠道、用户标识、状态、创建时间、最后活跃时间和消息数量，且 MUST NOT 包含完整消息正文。
- **FR-009**: 会话列表 MUST 能同时发现 CLI、REST、调度和内部调用产生的活动或归档会话，不改变各入口既有写权限。
- **FR-010**: 管理台会话视图 MUST 使用 `GET /api/v1/sessions` 展示真实会话，并能使用既有详情查询打开选中记录。
- **FR-011**: 管理台会话视图 MUST 提供加载、空数据、失败和重试状态，不得以硬编码或模拟数据替代运行时查询。
- **FR-012**: CLI、REST 和其他触发入口 MUST 继续只通过统一 `AgentService` 进入 ReAct 主流程，不得在接入层复制提示组装、模型循环或工具编排。
- **FR-013**: Spring AI 自动工具执行 MUST 保持关闭；同一工具意图 MUST 只由 `ToolExecutor` 执行一次并写入一条工具审计。
- **FR-014**: 每次模型调用，无论成功或失败，MUST 写入与 Session 关联的 `llm_calls` 记录；一次标准测试对话的成功记录数 MUST 恰好为 2。
- **FR-015**: 每次工具调用，无论成功、Sandbox 拒绝或执行异常，MUST 写入与 Session 关联的 `tool_invocations` 记录；一次标准测试对话的记录数 MUST 恰好为 1。
- **FR-016**: 一次标准测试对话完成后，Session 历史 MUST 按顺序保存用户消息、工具意图、工具结果和最终回复，长期记忆 MUST 能立即读到保存事实。
- **FR-017**: 系统 MUST 提供无需真实密钥的快速主流程测试和整机 HTTP 端到端测试，并将二者纳入默认构建门禁。
- **FR-018**: 真实 Provider 与公网场景 MUST 与无密钥门禁分离并明确标记为按需集成验证；缺少密钥时不得冒充通过。
- **FR-019**: 工作区根目录覆盖 MUST 继续支持测试使用临时 Agent、记忆和数据库资源，默认工作区行为不得变化。
- **FR-020**: 公开文档和示例配置 MUST 说明无密钥测试流程、会话列表契约及真实模型验证边界，且不得包含真实凭证。

### Key Entities

- **会话摘要**: 会话的轻量发现视图，包含身份、来源、状态、时间和消息计数，不包含消息正文或工具载荷。
- **确定性测试 Provider**: 由配置显式选择、按会话维护最小脚本状态的模型替身，只负责产生可预测模型响应。
- **主流程对账记录**: 同一会话在 Session、模型调用审计、工具调用审计和长期记忆中留下的相关痕迹集合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在零真实密钥、零公网依赖条件下，一次标准“记住……”对话 100% 产生非空回复、4 条有序历史消息、2 条成功模型审计、1 条成功工具审计和1条可立即读取的长期记忆事实。
- **SC-002**: 默认会话列表在任意数据量下最多返回 100 条摘要，排序和状态过滤测试通过率为 100%，响应中消息正文及敏感字段泄露数为 0。
- **SC-003**: 管理台能够列出自动化测试或人工对话产生的真实会话，并成功打开详情；加载、空态、失败和重试四类界面状态均有自动化证据。
- **SC-004**: CLI 与 REST 的确定性主流程测试均证明每个工具意图实际执行次数为 1，重复执行检出数为 0。
- **SC-005**: Provider 失败、Sandbox 拒绝和工具异常三类失败场景的审计覆盖率为 100%，每个场景后运行时仍可响应健康检查或后续独立请求。
- **SC-006**: 快速主流程测试和整机 HTTP 端到端测试均进入默认 `clean verify`，在无需真实外部服务的环境中通过率为 100%。
- **SC-007**: 真实模型集成验证与默认门禁严格分离；没有真实密钥或网络时，交付报告中未验证项披露率为 100%。

## Assumptions

- 本功能承接已完成的 Provider、ReAct、CLI、Tool、Memory、Sandbox、Scheduler、Web Service 和管理台基础能力，不在本节重建这些模块。
- 现有 `SessionManager.list()`、工作区根覆盖和会话详情接口属于可复用前序能力；实现阶段允许在保持兼容的前提下扩展有界列表契约。
- 会话列表是内网管理能力，本节沿用当前无认证边界；认证、RBAC、租户隔离和公网暴露治理不在范围内。
- 本节不新增审计查询 REST API；自动验收可直接通过持久化仓库核对 `llm_calls` 与 `tool_invocations`。
- 本节不完成第 28 节的定时通知串联、重启不失忆和多 Agent 并存验收，也不完成第 29 节的目录化插件 Agent 场景。
- 本节不要求在默认构建中调用真实模型、真实 Webhook 或公网天气服务；这些只作为具备密钥和网络时的人工集成验证。
