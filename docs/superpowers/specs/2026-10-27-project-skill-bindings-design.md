# 项目内部 Skill 引用设计

日期：2026-10-27。状态：用户已明确确认，已实现并通过普通权限完整自动验收。

## 目标

根据用户要求“修改 Windows 软连接，不让项目和系统相联系”，将 Skill 绑定改为由项目运行时解析的相对引用，不再依赖创建操作系统软连接的权限、Windows 开发者模式或管理员进程。项目移动后引用仍有效。

## 已批准方案

使用 `.oryxos/agents/<agent>/skills/<binding>.link` 普通 UTF-8 文本文件，每个文件仅写一行目标 Skill 目录的相对路径。路径相对于该引用文件所在的 `skills/` 目录解析。

示例：`.oryxos/agents/weather/skills/news.link` 内容为 `../../../skills/news`，目标为同一工作区 `.oryxos/skills/news/`。公共 Skill 内容仍只有一份，不复制到 Agent，不恢复 frontmatter `skills:` 清单。该机制在 Windows/Linux 使用相同规则。

确认后唯一绑定真相源由“相对软连接集合”修订为“Agent skills/ 下的 .link 引用文件集合”。为避免同时维护两套规则，不提供按操作系统切换的隐式回退；旧原生软连接给出显式迁移提示，不自动迁移或删除。

## 可选方案与取舍

- 原生软连接：无需应用解析，但保留操作系统权限依赖，不满足本次目标。
- 项目引用文件（推荐）：普通文件即可编辑、复制和版本管理，运行时统一解析；需要明确修订绑定契约。
- 复制 Skill 目录：会造成内容分叉，不满足公共 Skill 单一来源，排除。

## 加载与安全契约

1. `.link` 必须是普通文件；目录、操作系统软连接、未知格式和空目标均拒绝。文件仅允许一条非空路径，不支持多级引用文件、变量展开或脚本。
2. 拒绝绝对路径、盘符路径、UNC 路径；允许指向公共 Skill 的必要 `..` 段，先规范化再校验真实目标。
3. 目标必须是当前工作区公共 `skills/` 根内的目录；断引用、目标不存在、目录穿越、链接逃逸及 `SKILL.md` 逃逸均拒绝，不因 Windows 兼容而放宽真实路径校验。
4. 每次构建上下文重读引用文件和元数据，不缓存；修改、删除或重新绑定后下次构建生效。
5. 仍只预载 Skill 的 name、description 与可读取路径，不预载正文、脚本、参考资料或未绑定 Skill。
6. 由于引用文件不是文件系统目录别名，Prompt 中输出已校验的公共 `SKILL.md` 实际路径，而不是不存在的 `agents/<agent>/skills/<binding>/SKILL.md`。后续文件工具必须复用同一绑定解析结果进行可见性及路径校验，不能仅因路径位于公共根就允许访问未绑定 Skill。

- 保留用户已有修改；不修改 Windows 设置，不创建系统级链接，不自动迁移业务目录，不新增第三方依赖。
