# OryxOS 控制台首版管理视图

## 目标

在现有对话工作台左侧新增 Agent、Provider、Tool、Sandbox 白名单、长期记忆、运行状态、会话七个入口。默认进入会话页。切换视图时保留当前 Agent、会话和输入草稿。

## 方案

采用同一个 Vue 工作台内切换视图的方式，复用现有布局、API 客户端和会话状态。独立管理站点可以拥有单独部署和鉴权边界，但需要重复处理导航、会话跳转和部署，留待有独立部署需求时考虑。

## 首版行为

| 入口 | 行为 | 数据来源 |
| --- | --- | --- |
| Agent | 查看名称、描述、模型和工具，选择 Agent 后进入会话 | `GET /api/v1/profiles` |
| Provider | 查看已配置的 Provider 名称 | `GET /api/v1/info` |
| Tool | 查看全局工具，按 Agent 筛选 | `GET /api/v1/tools` |
| Sandbox 白名单 | 查看启动时生效的 HTTP 域名规则、文件根数量和允许的命令别名 | 新增 `GET /api/v1/sandbox/allowlist` |
| 长期记忆 | 按 Agent 查看核心和归档分区，提示归档截断 | `GET /api/v1/memory` |
| 运行状态 | 查看进程健康、版本和组件数量 | `GET /api/v1/health`、`GET /api/v1/info` |
| 会话 | 延续对话、恢复历史、新建及归档 | 现有 Session API |

各查询视图明确区分加载、空结果和失败，并提供重试。Sandbox 摘要取自实际装配时采用的规则，响应仅包含经过选择的字段。宿主机绝对路径、可执行文件位置及 Provider 凭证不进入返回值。运行状态中的健康检查表示应用可响应。

Sandbox 摘要沿用 `ApiResponse`，其中 `data` 包含排序后的 `httpDomains`、全局配置文件根数量 `fileRootCount` 和排序后的 `commandAliases`。空白名单返回空数组及零。文件根数量仅代表启动配置中的全局规则，Agent 目录与已绑定 Skill 的动态访问范围由原有沙箱计算。Boot 从装配后的规则提供只读快照，Web 通过窄接口读取。本版仍按工作台已有的受信环境部署边界使用。

## 后续扩展

导航用稳定的模块键注册，页面通过各领域的类型化查询函数读取数据。后续 Agent、Provider 的新增和编辑可以在各自页面接入独立的应用服务和 API 请求类型，现有查询与会话调用保持兼容。首版预留代码接入点，写接口、写权限、校验和配置生效方式由后续规格定义。

## 验收

验证七个导航、Agent 到会话跳转、会话状态保留、工具筛选、记忆分区和查询失败重试。后端测试验证 Sandbox 摘要与装配一致，且响应不含内部路径和凭证。运行前端测试及生产构建，并执行相关 Maven 回归。管理视图另立 Spec-Kit 规格，010 对话工作台作为依赖。
